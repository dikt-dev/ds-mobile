# 聊天页 UI 调整

> 日期：2026-10-25

## 1. 气泡

- 用户消息右对齐，浅紫气泡；
- AI 消息左对齐，白色气泡；
- 最大宽度 300dp，不再整行铺满；
- 圆角按发送方向收角（类似微信/QQ）；
- 每条消息显示：发送者 · 渠道 · 时间；
- 消息间距 12dp，聊天区浅灰背景；
- 跨天插入日期分隔条（`MM-DD`）。

截图：

- `screenshot-chat-ui2.png`

## 2. 文字与语音分离

- 普通文字不再显示「朗读」；
- 内容含 `[语音]` / `（语音）` 时，按标记切分：
  - 标记前的文字 → 独立文字气泡；
  - 标记后的内容 → **独立语音条**；
- 只有 `[语音]` 的回复不再把转写文字塞进同一个气泡。

## 3. 语音条

- 类似 QQ：圆角胶囊 + 圆形播放键 + 波形 + 时长；
- 时长按文本长度估算，点击播放 Azure TTS；
- 宽度随时长增加；
- 语音消息仍会后台预取，点击时优先命中缓存。

## 4. 图片

- 固定 220dp 宽、最大 260dp 高；
- 圆角 12dp，`ContentScale.Crop` 居中裁切；
- 不再 `fillMaxWidth()` 横向拉满。

## 5. 分享链接

- 识别 `b23.tv` / `bilibili.com` 链接；
- 卡片改成 QQ 风格：左侧封面 + 播放图标/时长，右侧标题、UP 主、两行摘要；
- 底部显示短链和「打开」，视频帧默认折叠，点「查看视频帧」再展开；
- App 内分享链接时，会把标题/UP/时长/摘要用隐藏的 `[BILI_META]` 块一起发给 AI；
- 设置页支持「在 App 内登录 B 站」：WebView 登录后自动保存 SESSDATA；
- 登录后手机直连 B 站接口，取官方 AI 总结、大纲和字幕；
- 手机端拉 B 站 storyboard 缩略图，按接口返回的 `img_x_len × img_y_len` 整张 sprite sheet 直接显示，不再强行裁 3×3；
- `image[]` 是多张 sprite sheet，`index[]` 是每帧对应的时间点（秒），需要按时间选帧时用 index 定位；
- 抽帧结果缓存，划走再划回不重下。

## 6. 视频 / GIF

- 输入栏新增「视频」；
- 视频/GIF 原文件上传 R2（≤60MB）；
- 聊天里存 `[视频:key]` / `[GIF:key]`；
- 视频用 Media3/ExoPlayer 内嵌播放，带鉴权 Header；
- GIF 用 `AnimatedImageDrawable` 动图播放；
- 旧 B 站标题/简介抓取逻辑保留，并新增 App 直连 + Worker 兜底。

## 8. 网页 / 抖音

- 普通网页链接渲染成「网页」卡片；
- 抖音链接渲染成「抖音」卡片；
- Worker 取标题/描述，随链接一起发给 AI；
- 抓不到元数据时保留链接卡片兜底。

## 9. 文件消息

- 发送文件后不再把整段解析文本铺在聊天里；
- 聊天记录显示文件卡片：文件名、大小、类型；
- 「查看解析内容」可展开解析出的文本；
- AI 仍收到完整文件正文；
- 使用 `[文件:name|size|mime]` 标记做本地展示，避免内容重复。

截图：

- `screenshot-chat-file.png`

## 10. 动图

- 图片消息优先用 `ImageDecoder` 解码；
- GIF/动态 WebP 用 `AnimatedImageDrawable` 播放；
- 静态图片仍走同一 ImageView，保持 220dp 对齐。

## 12. 滚动缓存

- 图片/GIF 解码结果进入 `LruCache`，划走再划回不重新下载；
- B站/网页预览元数据缓存 32 条，避免反复请求；
- 视频 ExoPlayer 按 key 复用，划走只暂停不释放，划回来不重新 prepare；
- 退出重配对时可调用 `MediaCaches.clear()` 清空。

## 14. 消息分句与语音条

- 分句时会跟踪 `（）`、`()`、`【】`、`[]` 和 `「」`、`“”`，括号/引号内的标点不拆；
- 一个动作描述括号不会被拆散；
- 文本中出现 `【语音】` / `[语音]` / `（语音）` / `【语音消息】` / `[语音消息]` 时，语音段被单独拆成语音条；
- 引号 `「...」` 内的语音只取引号内容，后面的文字继续分句；
- 新到达的 AI 回复逐句揭示，每 180ms 显示下一句；
- 历史消息首次打开时直接完整显示，不重播动画；
- 流式输出阶段同样逐句出现，最后才由数据库消息接管；
- 等待回复时显示「大肥鱼 · 正在输入…」；
- 流式输出时逐句生成气泡，语音段先显示「语音生成中…」；
- 语音条右侧「转文字」可展开/收起该语音的转写文本。

## 16. 磁盘缓存

- 统一上限 **1GB / 1000 个文件**，按最旧文件淘汰；
- 图片/GIF 字节写入 `cache/api-media`，App 重启先读磁盘；
- B 站/网页预览元数据写入 `cache/api-media`（带 B 站登录态的 hash，换账号自动失效）；
- B 站 storyboard sprite 写入 `cache/bili-cache`，重启不重新下载；
- 内存中仍保留解码后的 Drawable / 预览对象 / ExoPlayer，滚动不重解码；
- 视频仍按 HTTP 流式播放，不做整段落盘，避免单个大视频占满缓存。

## 17. 打开即最新

- 首次进入聊天页用 `scrollToItem` 直接定位到列表底部哨兵，不使用 `animateScrollToItem`；
- 首次定位会等 4 帧重新测量后再贴底，避免长消息/图片高度未算完时差一截；
- 首次定位完成前聊天列表透明，避免先闪一下顶部再滑到底；
- 后续新消息才使用动画滚动；
- 键盘使用 `adjustResize`，输入框固定在键盘上方，不再整页被顶上去；
- 监听 `WindowInsets.ime`，键盘弹出后重新贴到列表底部，最新消息会跟着上移。

## 18. 逐句输出

- 先等完整 AI 回复到齐，不做半截流式重排；
- 如果有语音段，先把语音合成缓存好，再开始输出；
- 新 AI 回复每 **1 秒**显示下一句；
- 每显示一句后延迟 120ms 再平滑滚到底部；
- 手动滚动过程中跳过自动滚动，避免抢滚动；
- 历史消息不播放逐句动画。

## 19. 发送状态

- 发送中只显示「大肥鱼 · 正在输入…」，不显示「发送中」；
- 待发送气泡不再显示「待发送」；
- 成功同步后，用户气泡左侧显示「已读 ✓」绿圈；
- 发送失败显示「失败 ×」红圈，并可点重试；
- 只有失败/同步失败才显示错误状态。

## 20. 输入区

- 底栏白底 + 阴影；
- 图片/文件/语音按钮单独一行；
- 输入框 + 发送按钮单独一行，避免挤压。
