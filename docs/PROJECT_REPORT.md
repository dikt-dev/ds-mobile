# DS-Mobile 项目报告（评审稿）

> 项目代号：**DS-Mobile**  
> 目标设备：红米 K60（23013RK75C / mondrian，Android 15 / API 35，arm64-v8a）  
> 使用者：仅本人，私有项目，不上架  
> 文档版本：v1.0（已确认）  
> 日期：2026-10-25  
> 状态：**已确认，进入阶段 0**

---

## 1. 项目背景

### 1.1 现状

目前手机端链路是：

```text
QQ → NapCat → Termux/proot Ubuntu → ds-qq-client → Cloudflare Worker → DeepSeek
```

存在以下问题：

- 依赖 QQ 和 NapCat，QQ 掉线、风控、协议变更都会影响使用；
- Termux + proot + QQ + Xvfb + watchdog 链路长、占内存、耗电；
- 消息要经过多层转发，首字延迟和语音延迟高；
- 维护点多，排障困难；
- 手机端后台容易被系统或 QQ 自身打断。

### 1.2 项目机会

- 不再走 QQ 协议，App 直接对接自己的 `ds-memory` Worker；
- 手机端只保留一个原生 Android App；
- 媒体、TTS、ASR、文件解析尽量放在手机本地，降低服务器和带宽压力；
- 只适配 K60，不上架，不兼容其他机型，可以大幅降低复杂度；
- 可以针对 HyperOS 做后台保活，满足“划掉后台仍收”。

## 2. 终极目标

### 2.1 一句话目标

> **用红米 K60 上的一个私有 Android App，完全取代 QQ + Termux/NapCat 手机端，成为 `ds-memory` 的唯一移动入口；支持文字、语音、图片、视频、动图，划掉后台仍能稳定接收；媒体、语音、文件解析尽量在本地完成，降低服务器压力和回复延迟；长期可维护、可调试、可恢复。**

### 2.2 量化目标

| 指标      | 目标值                                          | 说明                      |
| --------- | ----------------------------------------------- | ------------------------- |
| 后台接收  | 划掉任务后 8 小时，50 条测试消息成功率 ≥ 99%    | HyperOS 白名单 + 前台服务 |
| 重启恢复  | 手机重启后自动恢复接收                          | BOOT_COMPLETED + 自启动   |
| 文本发送  | 点击发送到 Worker 接受，p95 ≤ 1.5 秒            | 不含模型生成              |
| AI 首字   | 首 token 到达 p95 ≤ 3 秒                        | 受网络和模型影响          |
| 本地 TTS  | 首段音频 ≤ 800 毫秒                             | 系统/本地 TTS             |
| Azure TTS | 首段音频 ≤ 2 秒                                 | 网络正常                  |
| 图片      | 5MB 图片压缩上传 ≤ 3 秒                         | 本机 Wi-Fi/5G             |
| 视频      | 1 分钟 720p 转码 ≤ 15 秒                        | K60                       |
| PDF       | 50 页文字版解析 ≤ 5 秒                          | 本地                      |
| 压缩包    | 50MB / 100 条目 ZIP ≤ 15 秒                     | 受文件类型影响            |
| 稳定性    | 崩溃率 < 0.5%，无重复/丢失消息                  | 500 条消息压测            |
| 内存      | 常驻 ≤ 400MB                                    | 不含系统                  |
| 耗电      | 8 小时待机 ≤ 5%                                 | 前台服务 + 轮询           |
| APK       | ≤ 180MB                                         | 含解析/OCR/媒体库         |
| 安全      | 无 Worker API Key 硬编码；Azure Key 存 Keystore | 私有 APK                  |

> 指标是验收目标，不是承诺值；以 K60 实测为准。

### 2.3 非目标（明确不做）

- 不做 iOS；
- 不上应用商店；
- 不做多用户、多设备同时在线；
- 不做群聊、语音通话、视频通话；
- 不重新实现 QQ 协议；
- 不做端到端加密（AI 在服务端，E2E 意义有限）；
- 不在手机上跑大语言模型；
- 不提供完整 Linux shell（只提供受限调试命令 + SFTP）；
- 不保证“强行停止”后还能接收（Android 系统限制，划掉后台可以）。

## 3. 范围与原则

### 3.1 范围

只服务一台 K60、一个用户、一个 Worker 后端。

必须支持：

- 文字消息发送/接收；
- 语音消息录制、转写、播放；
- 图片、视频、动图（GIF/WebP）发送；
- 划掉后台仍能收消息；
- 本地通知、未读、历史记录；
- Azure TTS / 本地 TTS 可配置；
- Azure STT / 本地 ASR 可配置；
- 常见文档解析：PDF、DOCX、XLSX、PPTX、TXT/MD/CSV/JSON；
- 压缩包解析：ZIP 起步，RAR/7z 第二阶段；
- SSH/SFTP/FTP 调试服务；
- 设置页：服务器地址、设备 Token、Azure Key/Region、TTS/ASR 模式、调试开关。

### 3.2 设计原则

1. **本地优先**：能在手机做的解析、压缩、转码、TTS、ASR 不放到服务器。
2. **简单可靠**：优先 3~5 秒增量轮询，不一开始就上复杂长连接。
3. **单设备适配**：只为 K60 / HyperOS 做保活，不为通用机型做兼容。
4. **可回退**：QQ/Termux 保留到 App 稳定后再退役。
5. **安全默认**：调试服务默认关闭，Azure Key 和 Token 不落明文日志。
6. **消息幂等**：所有消息有服务端 id，客户端按 id 去重，重试不重复显示。

### 4.2 消息流

**文本发送**

```text
输入文字 → Room 本地插入 outbox → POST /v1/chat/completions (stream)
→ 逐段渲染 → 完成后落库 → 更新会话
```

**接收**

```text
前台服务每 3~5 秒 GET /api/app/events?after_id=...
→ 新消息写入 Room → 本地通知 → UI 刷新
```

**语音发送**

```text
录音 → VAD/降噪 → 本地 ASR（或 Azure STT）
→ 得到文字 → 按文本消息发送
→ 可选保留音频用于本地播放/上传
```

**图片/视频/GIF**

```text
选择/拍摄 → 本地压缩/转码 → R2 预签名 PUT
→ 发送消息（带 R2 key + 元数据）
→ 接收端下载/缓存/显示
```

**文件解析**

```text
选择文件 → 本地类型识别 → 解析/OCR/解压
→ 生成结构化文本（≤30K 字符）
→ 作为消息内容发送给 Worker
→ 原始文件默认不上传（可选上传）
```

### 4.3 服务端改动

| 接口                        | 用途                             | 状态 |
| --------------------------- | -------------------------------- | ---- |
| `POST /api/app/pair`        | 一次性配对码换设备 Token         | 新增 |
| `GET /api/app/events`       | 按 `after_id` 拉新消息           | 新增 |
| `POST /v1/chat/completions` | 复用，`X-Client-Channel: mobile` | 复用 |
| `POST /api/app/upload-url`  | R2 预签名上传                    | 新增 |
| `GET /api/app/health`       | 版本/连通性                      | 可选 |
| `/api/qq/outbox`、web_sync  | QQ 退役后删除                    | 清理 |

D1 继续使用现有 `messages` 表，App 消息 `channel = 'mobile'`；Web 端仍可看全部渠道。

### 4.4 技术选型

| 层       | 选型                                     | 理由                            |
| -------- | ---------------------------------------- | ------------------------------- |
| 语言/UI  | Kotlin + Jetpack Compose                 | 原生、单机型、开发效率高        |
| 最低版本 | minSdk 35 / target 35                    | K60 是 Android 15，减少兼容分支 |
| 网络     | OkHttp + Retrofit + SSE/轮询             | 简单稳定                        |
| 本地库   | Room + DataStore                         | 消息/设置                       |
| 媒体     | Media3 + CameraX + MediaCodec/FFmpegKit  | 播放/拍摄/转码                  |
| 图片     | Coil                                     | 图片/GIF 展示                   |
| 文档     | PDFBox-Android、OOXML 自定义解析、zip4j  | 控制 APK 体积                   |
| OCR      | ML Kit 中文文字识别                      | 离线、隐私                      |
| TTS      | Azure Speech REST / Android TextToSpeech | 可配置                          |
| ASR      | Azure STT / Whisper.cpp/Vosk             | 可配置                          |
| 后台     | Foreground Service + WorkManager         | 划掉仍收                        |
| 调试     | Apache MINA SSHD + Apache FtpServer      | 纯 Java，免 root                |
| 构建     | Gradle Wrapper + JDK 17 + SDK 35         | 已就绪                          |

## 8. 验收标准

### 8.1 功能验收

- [ ] 文字发送/接收/历史/未读；
- [ ] 划掉后台 8 小时仍收（暂缓，不作为当前出口条件）；
- [ ] 重启手机自动恢复；
- [ ] 语音录制、转写、播放；
- [ ] 图片/视频/GIF 发送与预览；
- [ ] Azure TTS / 本地 TTS 切换；
- [ ] Azure STT / 本地 ASR 切换；
- [ ] PDF/DOCX/XLSX/PPTX/TXT 解析；
- [ ] ZIP 解析与安全限制；
- [ ] SSH/SFTP 调试；
- [ ] 设置页、日志、备份。

### 8.2 性能验收

| 项                   | 目标       |
| -------------------- | ---------- |
| 文本发送 ack         | p95 ≤ 1.5s |
| AI 首 token          | p95 ≤ 3s   |
| 本地 TTS 首段        | ≤ 800ms    |
| Azure TTS 首段       | ≤ 2s       |
| 5MB 图片上传         | ≤ 3s       |
| 1 分钟 720p 视频转码 | ≤ 15s      |
| 50 页 PDF            | ≤ 5s       |
| 50MB ZIP             | ≤ 15s      |
| 常驻内存             | ≤ 400MB    |
| 8h 待机耗电          | ≤ 5%       |

### 8.3 稳定性验收

- 500 条消息压测，无重复、无丢失；
- 断网/切网/飞行模式恢复；
- 20 条消息/分钟不 ANR；
- 进程被杀后能恢复；
- 连续运行 72 小时无崩溃。

### 8.4 安全验收

- APK 内无 Worker API Key；
- Azure Key 存 Keystore；
- 调试服务默认关闭、仅局域网、密钥登录；
- 文件解析不越权、不执行宏、不路径穿越；
- 日志不打印 Key/Token。

## 9. 风险与对策

| 风险                        | 等级 | 对策                                                                     |
| --------------------------- | ---- | ------------------------------------------------------------------------ |
| HyperOS 杀后台              | 高   | 前台服务 + 自启动 + 无限制 + 锁定任务 + WorkManager 兜底；只承诺划掉后台 |
| 用户强行停止                | 中   | 明确不支持；重新打开恢复                                                 |
| MINA SSHD 在 Android 兼容性 | 中   | P0 spike；失败则用 SFTP-only 方案/原生 dropbear                          |
| 文件解析 OOM/zip bomb       | 高   | 大小/条目/深度/压缩比限制；流式解析；超时取消                            |
| 视频转码发热                | 中   | 720p/时长限制；前台服务；失败降级发原视频/文件                           |
| Azure Key 泄露              | 中   | Keystore；不硬编码；可轮换；私有 APK                                     |
| R2 大文件/CORS              | 中   | 预签名/分片；限制大小；失败重试                                          |
| Cloudflare 请求限制         | 低   | 3~5 秒轮询；单用户；必要时改 SSE                                         |
| 消息重复/乱序               | 中   | 服务端 id + 本地游标 + 幂等                                              |
| 8GB PC 编译慢               | 低   | 只连真机；Gradle 2GB；D 盘缓存                                           |
| 解析库体积/方法数           | 中   | 自定义 OOXML；R8；只 arm64                                               |
| 依赖库许可证                | 低   | 选 Apache/BSD；FFmpeg 注意 LGPL/GPL                                      |
