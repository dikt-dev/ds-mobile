# 主动消息为什么没弹通知（2026-10-31 排查）

## 现象

那天她发了主动消息（18:00 的 random），手机没有通知，打开 App 才看到。

## 链路是怎样的

App 有两条完全不同的收信路径，混在一起看就会误判：

| 路径 | 走什么 | 何时生效 |
| --- | --- | --- |
| 后台常驻 | `KeepAliveService` 5 秒轮询 → 本地通知 | 只在「设置 → 通知 → 后台常驻」开着时 |
| 到点提醒 | `ProactiveScheduler` 挂 AlarmManager 闹钟 → 醒来拉一次增量 → 弹通知 | 只要闹钟挂上了就生效 |

这台机器的后台常驻是**关着**的（服务端心跳 version=`ds-mobile/background-off`，19:45 那条），
所以只有「到点提醒」这一条路。

## 根因

`ProactiveScheduler.refresh()` 只在四个时机被调用：

1. 进聊天页（`LaunchedEffect(token)`，token 不变就不会重跑）
2. 开机广播（`BootReceiver`）
3. 设置里开/关通知
4. 诊断页「重新计算闹钟」

而且 `refresh()` 只挂**当天**的档位。于是：**某一天没打开过 App（也没重启），那天就一个闹钟都没有** —
消息照常生成、照常进聊天记录，但没有任何东西会醒来叫你。18:00 那条就是这样错过的
（早上 07:46 那条同样没通知，正好互相印证）。

## 已经改掉的三处

1. **每日翻页闹钟**：`ensureDailyRollover()` 挂一个每天 00:10 的闹钟（`slot=rollover`），
   醒来只做一件事——重算当天计划、把明天的档位挂上，然后把自己推到再下一天。
   只要 App 在最近打开过一次，之后每天都会自动续上。
2. **回前台就对账**：`ChatActivity.onResume` 里也调一次 `refresh()`，
   不再依赖 `LaunchedEffect(token)`（token 不变时它不会重跑）。
3. 翻页闹钟跟着 `cancelAll` 一起取消，避免关掉通知后还留着残留闹钟。

## 顺带确认的两件事

- 服务端队列里那条 `pending=1` 是给 QQ 插件（AstrBot）的，App 不走这条；
  6 小时租约窗口过后就自然作废，不会在半夜补发一条过期的"傍晚好"。
- 主动消息本身没问题：`messages` 里有 id 1413、`proactive_log` 记录 score=52、
  原因「处于用户常活跃时段」。

## 怎么自查

设置 → 连接与诊断：

- 「最近醒来记录」：看 `slot` 与「延迟 N 分 取到 M」；整天没有记录 = 闹钟没挂上
- 「测试通知」：只验通知权限，不验闹钟
- 「重新计算闹钟」：手动挂当天的；改完这版之后正常不需要再点
